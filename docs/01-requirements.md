# 需求与成功标准

用户是内容运营人员。目标是知道每项素材是否合规、有没有排期冲突、需要补什么，以及草稿是否确实保存。

输入包含请求 ID 和 1–8 个不重复素材 ID；每项指定一个渠道和带时区偏移的硬性时间。素材、规则、已有时段可以使用合成文件；按输入顺序逐项处理，批次允许部分成功。一个渠道在同一时刻只允许一个占用；已保存草稿占用排期，未确认提案不占用。比较的是离散发布时间；备选仅搜索同渠道、同日、往后 1–3 小时。

逐项输出审核、排期和写入状态，缺失字段、规则依据、原始时间、备选和确认状态、草稿 ID、失败原因及建议下一步。核心验收是正常可保存、缺资料不保存、规则风险阻断、冲突需确认、重放不重复写、保存失败不虚报。真实模型应在收到不同查询结果后走出两条路径；回合或工具预算用尽应停止。

扩展验收：持久化提案可在新进程中确认；绑定同一请求、素材、渠道和具体时段，确认前重新审核并重查占用，失败可安全重试。重复确认返回同一草稿。仍然只保存草稿，不接真实发布。
