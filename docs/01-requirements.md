# 需求与成功标准

## 用户与目标

内容运营人员提交待处理素材和硬性发布时间。系统逐项回答四个问题：素材能否用于指定渠道，要求的时间是否可用，发生冲突时有哪些备选，以及草稿是否实际保存。运营人员可以据此补资料、处理风险、确认改期或重试。

例如，素材 M01 审核通过，原始要求是 18:00。如果该时段已占用，Agent 可以建议已查询到的 19:00，并返回待确认提案。结果同时保留 18:00 的原始要求。运营人员确认提案后，系统重新检查素材和 19:00 的占用，再尝试保存草稿。

## 输入与输出

| 输入 | 字段与校验 |
| --- | --- |
| 排期请求 | `requestId` 用于识别重放。`items` 包含 1–8 项，素材 ID 在同一请求内唯一。每项提供 `assetId`、`channel` 和带时区的 `requiredTime`。 [请求样例](../examples/paired.input.json) |
| 素材数据 | 按素材 ID 查找标题、授权状态及许可渠道。未知素材或缺少必填字段时，输出需补充项。 [素材数据](../data/assets.json) |
| 审核规则 | 配置包含规则版本、必填字段、授权规则 ID 和渠道规则 ID。已知违规返回规则 ID 和原因。 [规则配置](../data/rules.json) |
| 已有排期 | 按渠道和带时区的时段导入占用。同一渠道、同一 UTC 时间点只能有一个占用。 [占用样例](../data/occupied.json) |

每项输出审核状态、规则版本、风险和缺失字段，排期部分保留原始时段、候选时段和确认状态。保存部分提供 `saveStatus` 和 `draftId`，运行部分提供状态、原因、停止原因和建议的下一步。批次按输入顺序处理，已保存项和未完成项可以同时出现。

## 范围与边界

- 支持 CLI 导入合成素材、规则和排期，逐项核验后保存排期草稿。真实模式调用模型，Mock 模式可在没有 API 凭据的环境中复现流程。
- 硬性时段不可用时，仅搜索同渠道、同日、向后 1–3 小时的离散候选。找不到候选时返回未完成原因。
- 未确认的提案不占用时段。跨进程确认需要使用生成提案时的 SQLite 文件和 `proposalId`。确认时重新审核并检查候选时段，成功后才创建草稿。
- 当前范围以合成规则和离散时点为限。跨日搜索、时间区间、外部日历、账号权限和真实发布均在范围外。

## 成功标准

| 验收场景 | 通过条件 |
| --- | --- |
| 正常排期 | 审核通过且指定时段可用。系统返回真实草稿 ID，SQLite 中有且仅有一条对应记录。 |
| 素材信息缺失 | 输出需补充的字段，草稿数为零。 |
| 规则风险 | 输出命中的规则和原因，阻断保存。 |
| 时段冲突 | 模型观察到占用后另起一轮查备选。原始时段保留，备选标为待确认，草稿数为零。 |
| 重复提交 | 同一请求在同一数据库中复用原草稿 ID。同一请求 ID 携带不同内容时明确拒绝。 |
| 保存失败 | 输出 `WRITE_FAILED`，数据库不保留未提交的草稿。 |

真实模型的正常和冲突场景应留存两条独立轨迹，能核对工具参数、观察结果、下一步动作及依据。回合或调用预算耗尽时，运行返回未完成及停止原因，已提交的草稿仍保留回执。人工确认需通过时段被抢占、授权变化和重复确认等检查。 [验收记录与复现方式](03-evaluation.md)
