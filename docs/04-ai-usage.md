# 项目职责与 AI 使用说明

## 我的职责

我负责选题、技术方向、验收取舍和交付范围。我选定第 1 题「素材审核与发布排期 Agent」，选择 DeepSeek Flash 并在本机完成模型配置。迭代过程中，我把评审重点放在 Agent 的架构、决策链路、测评体系和 Harness 治理，并要求改动落到系统行为上。

## 我推动的工程决策

| 我的决策 | 项目变化与验收证据 |
| --- | --- |
| 用两条真实模型轨迹验收 Agent 的决策链路。 | 同一素材、同一请求仅改变 18:00 的占用。空闲时模型调用保存工具，冲突时模型在后续回合补查备选并给出待确认提案。评测同时核对动作顺序和数据库写入。 [空闲轨迹](../examples/live/available.trace.jsonl) · [冲突轨迹](../examples/live/conflict.trace.jsonl) |
| 把工具权限作为 Harness 的迭代重点。 | 系统核对回合开始时开放的权限和调用前仍有效的权限。首次保存成功或失败后，同一回复里的第二次保存都会在进入存储层前被拦截。 [权限治理回归](../tests/improvements.test.ts) |
| 按题目逐项复核，把预算边界纳入修复。 | 最后一次调用已提交草稿且预算耗尽时，输出同时保留未完成的运行状态和已保存的草稿回执。回归覆盖回合上限、调用上限、写入失败和重复提交。 [预算与回执回归](../tests/agent.test.ts) |
| 收敛交付材料，减少评审查找证据的成本。 | 验收表逐项关联输入、实际输出、Trace 和数据库快照。保留必验场景和关键边界的记录，清理重复结果。 [验收索引](03-evaluation.md) |

验收采用两条独立标准。工具轨迹用于判断模型是否在观察后选择了正确动作，输出和 SQLite 快照用于确认草稿状态、数量及 ID。这样可以定位模型决策、权限控制或存储写入各自的问题。 [评测设计](03-evaluation.md#评测设计) · [测试日志](../examples/test-results.txt)
