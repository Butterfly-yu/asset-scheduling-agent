# AI 使用说明

## 我在项目中的工作

我选择了素材审核与发布排期题，确定使用 DeepSeek，并在本机配置了模型接口。讨论方案时，我要求把项目的主要价值放在 Agent 架构、决策链路、测评和 Harness 治理上。这项要求推动迭代直接落到运行逻辑，例如在每次工具执行前重新核对权限。

我提供了完整题目要求，要求逐条核对已实现能力、实际轨迹和交付文件，并在看到预算状态与草稿回执的边界问题后确认修复。最后，我要求精简重复记录，保留能直接说明通过条件的输入、输出、Trace 和数据库快照。

| 我的要求或操作 | 落到项目中的变化 | 验证证据 |
| --- | --- | --- |
| 确定题目和模型，在本机完成模型配置。 | 使用 DeepSeek Flash 验证同一请求在空闲与冲突下的动作变化。 | Codex 执行了真实模式验收并留存两条轨迹。 [空闲](../examples/live/available.trace.jsonl) · [冲突](../examples/live/conflict.trace.jsonl) |
| 要求增强 Harness 的实际治理能力。 | 增加回合初始授权与调用前授权的核对，记录放行、拒绝原因和预算。 | Codex 执行回归测试，核对同一回复中的第二次保存无法进入存储层。 [治理验证](03-evaluation.md#harness-与预算) |
| 要求按原题逐项检查，并确认处理发现的预算状态问题。 | 预算耗尽报告未完成，同时保留已提交的草稿回执。评估表逐例链接原始证据。 | Codex 执行了回合上限、调用上限及失败原因的回归测试。 [测试用例](../tests/agent.test.ts) |
| 要求整理交付并清理重复测试记录。 | 演示输出写入本地目录，仓库保留题目验收和边界证据。 | Codex 验证了 11 个离线场景，检查新运行没有覆盖提交的记录。 [复现命令与证据](03-evaluation.md) |

## AI 辅助和代码修改

Codex 辅助了需求拆解、方案比较、源码与测试编写、故障注入、真实接口调用、证据整理和文档修改。工具权限判定、SQLite 事务、轨迹评测及后续回归修复的代码变更均由 Codex 执行。个人参与集中在题目和模型选择、本机配置、提出验收口径、判断迭代优先级和确定交付范围。

## 验证和可追溯记录

我提供验收要求并要求将动作和持久化结果一并核对。实际命令由 Codex 执行。自动测试检查规则、权限、回滚、幂等和预算边界，真实模型轨迹验证决策分支，CLI 输出与 SQLite 快照验证业务结果。仓库中的素材和排期均为合成数据，模型密钥保存在本机忽略文件中。 [评估记录](03-evaluation.md) · [实际测试日志](../examples/test-results.txt)
