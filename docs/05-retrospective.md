# 复盘

最难的部分是划清模型建议与可提交结果：工具看见空闲后，写入时可能已经被占用；模型认为保存成功，也不能替代数据库回执。把规则校验、确认与写入约束放在可信代码中，再用故障注入和重放验证，比仅检查模型文本可靠。

另一个教训是离线可复现和真实决策需要分别验证。最初拟采用 Pi Core；npm 镜像在当前执行环境不可访问，最终使用零第三方依赖的原生工具调用循环。本地协议测试可确认消息传递，不能推断模型是否会选择正确动作。

真实模型两条轨迹已验证。冲突时 Flash 查了候选，但多发出一次被拦截的保存调用。后续可减少这种无效调用，并用多次重复评测检查改动。未完成：持久化人工确认提案、任意时段区间和外部日历。若增加具名提案和确认续跑，确认时仍需重查占用。

实际用时：从创建首批项目文件到保存离线测试日志约 10 分钟（按文件时间戳估算，不含此前选题设计或后续文档整理）。候选人应在最终提交时记录个人实际用时和远端验收用时。
